* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

=mcpkit= is a registration-based framework for defining Model Context Protocol (MCP) services and tools in GNU Emacs and exposing them over HTTP JSON-RPC 2.0 using =web-server.el=.

Key capabilities:
- *Declarative Service and Tool Definitions*: Easily construct services and register tools with JSON schema metadata, documentation, and parameter decoders.
- *Synchronous and Asynchronous Execution*: Tool handlers can return immediate values or accept a completion callback for asynchronous operations.
- *Custom Serialization Pipelines*: Built-in MCP content packaging with hooks for customized input decoding and output encoding.
- *Flexible Multi-Service Routing*: Host multiple logical MCP services on a shared HTTP server instance with configurable collision policies (=namespace= prefixing or strict =error= checking).
- *Tabulated Interactive Dashboard*: Full-featured =tabulated-list-mode= interface (=mcpkit-list-services=) to inspect, start, stop, and monitor registered services.
- *Extensible Ecosystem*: First-class support for domain packages (such as `hitl-mcp` and `denote-mcp`) registering dedicated services and tools.

** ELPAish (Recommended)
:PROPERTIES:
:CUSTOM_ID: elpaish-recommended
:END:

Add the ELPAish repository to ~package-archives~:

#+BEGIN_SRC emacs-lisp
(add-to-list 'package-archives
             '("elpaish" . "https://tychoish.github.io/elpaish/snapshot/") t)
(package-refresh-contents)
#+END_SRC

Install with =package-install=:

#+BEGIN_SRC emacs-lisp
(package-install 'mcpkit)
#+END_SRC

To verify package signatures, import the ELPAish signing key into
=package.el='s keyring and enable signature checking:

#+BEGIN_SRC emacs-lisp
(url-copy-file "https://tychoish.github.io/elpaish/elpaish-keyring.gpg"
               "elpaish-keyring.gpg" t)
(package-import-keyring "elpaish-keyring.gpg")
(setq package-check-signature t)
#+END_SRC

** Manual Installation
:PROPERTIES:
:CUSTOM_ID: manual-installation
:END:

Clone the repository to your local load path:

#+BEGIN_SRC sh
git clone https://github.com/tychoish/mcpkit.el.git ~/.emacs.d/site-lisp/mcpkit
#+END_SRC

Then require it in your Emacs configuration:

#+BEGIN_SRC emacs-lisp
(add-to-list 'load-path "~/.emacs.d/site-lisp/mcpkit")
(require 'mcpkit)
#+END_SRC

With Emacs 29.1+, you can also use ~package-vc-install~:

#+BEGIN_SRC emacs-lisp
(package-vc-install '(mcpkit :url "https://github.com/tychoish/mcpkit.el.git"))
#+END_SRC

** Key Options & Customization
:PROPERTIES:
:CUSTOM_ID: key-options--customization

- ~mcpkit-log-verbose~: When set to ~t~, log the full decoded request and response JSON payloads to the service's log buffer. Default is ~nil~.

** Agent-shell integration

The optional =mcpkit-agent-shell= module is available when included in the
installed MCPKit version; MCPKit itself does not require agent-shell.  Load the
module explicitly and enable the global mode, before or after agent-shell loads:

#+BEGIN_SRC emacs-lisp
(require 'mcpkit-agent-shell)
(mcpkit-agent-shell-mode 1)
;; To remove the integration, leaving shared services running:
(mcpkit-agent-shell-mode -1)
#+END_SRC

New sessions resolve the current endpoint lazily.  The mode preserves existing
global servers, and reports a collision with a server named =emacs=.  An agent's
=:mcp-servers= setting takes precedence over the global list; include MCPKit in
that setting separately if needed.  Explicit client environment entries win
over the bridge's =MCPKIT_PORT=, =EMACS_MCP_PORT=, =EMACS_MCP_URL=,
=EMACS_SPRITE_ID=, and =EMACS_SERVER_NAME= defaults.  These variables identify
the direct service even when the ACP endpoint uses a proxy.

Proxy routing requires a running MCPKit proxy with a registered route from the
current =sprite-instance-id= to the direct service port.  Otherwise the ACP
endpoint uses the direct URL.

** Defining a Service and Synchronous Tool
:PROPERTIES:
:CUSTOM_ID: defining-a-service-and-synchronous-tool
:END:

Define a service and attach synchronous tools using ~mcpkit-register-tool~:

#+BEGIN_SRC emacs-lisp
(defvar my-math-service
  (mcpkit-define-service 'math
    :port 8765
    :description "Mathematical utility service"))

(mcpkit-register-tool add my-math-service
  :description "Add two numbers together."
  :input-schema '(:type "object"
                  :properties (:a (:type "number" :description "First number")
                               :b (:type "number" :description "Second number"))
                  :required ["a" "b"])
  (+ (plist-get args :a) (plist-get args :b)))
#+END_SRC

** Defining an Asynchronous Tool
:PROPERTIES:
:CUSTOM_ID: defining-an-asynchronous-tool
:END:

Pass ~:async t~ when the handler needs to perform non-blocking I/O or background processing. In async mode, ~done~ is bound in the macro body:

#+BEGIN_SRC emacs-lisp
(mcpkit-register-tool fetch-data my-math-service
  :description "Fetch remote data asynchronously."
  :async t
  (run-with-timer 0.5 nil
                  (lambda ()
                    (funcall done nil "Fetched remote content"))))
#+END_SRC

** Custom Argument Decoding and Result Encoding
:PROPERTIES:
:CUSTOM_ID: custom-argument-decoding-and-result-encoding
:END:

You can supply ~:decode~ and ~:encode~ hooks to customize parameter transformations and response formatting:

#+BEGIN_SRC emacs-lisp
(mcpkit-register-tool transform-text my-math-service
  :description "Transform text string with custom codec."
  :decode (lambda (plist) (plist-get plist :text))
  :encode (lambda (result)
            (list (list :type "text" :text (format "TRANSFORMED: %s" result))))
  (upcase args))
#+END_SRC

** Starting Services and Tool Collision Management
:PROPERTIES:
:CUSTOM_ID: starting-services-and-tool-collision-management
:END:

Start a service with ~mcpkit-start-service~. When multiple services share a server instance, specify ~:on-collision~:

#+BEGIN_SRC emacs-lisp
;; Automatically namespaces colliding tools as `<service-name>__<tool-name>'
(mcpkit-start-service 'math :on-collision 'namespace)

;; Alternatively, signal an error if tool names clash:
;; (mcpkit-start-service 'math :on-collision 'error)
#+END_SRC

To stop a running service:

#+BEGIN_SRC emacs-lisp
(mcpkit-stop-service 'math)
#+END_SRC

** Managing Services via Tabulated UI
:PROPERTIES:
:CUSTOM_ID: managing-services-via-tabulated-ui

Run =M-x mcpkit-list-services= to open the interactive services buffer:

#+BEGIN_EXAMPLE
Service               Status      Port      Tools     Description

- ~k~: Stop the service at point.

** Core Emacs Service (mcpkit-emacs)
:PROPERTIES:
:CUSTOM_ID: core-emacs-service-mcpkit-emacs
:END:

The bundled ~mcpkit-emacs~ module exposes core GNU Emacs management, buffer inspection,
and safe evaluation to AI agents:

#+BEGIN_SRC emacs-lisp
(require 'mcpkit-emacs)
(mcpkit-start-service 'emacs :port 8765)
#+END_SRC

Exposed MCP tools:
- ~emacs_server_status~: Return Emacs process status, versions, uptime, and active mcpkit services.
- ~emacs_get_buffer~: Inspect buffer metadata and contents by name or visited file path.
- ~eval~ (exposed as ~emacs__eval~; formerly ~emacs_eval~): Last resort. Evaluates arbitrary Emacs Lisp; prefer a specific tool found with ~search_tools~.
- ~mcpkit_stats~: Per-tool call statistics as structured rows (optional ~tool~ and ~limit~ arguments).

The ~mcp_buffer_list~, ~mcp_buffer_kill~, ~mcp_buffer_save~, ~mcp_buffer_revert~ and
~mcp_get_messages~ duplicate tools were removed; those names (and ~emacs_eval~) still
work through ~mcpkit-tool-aliases~ and resolve to the ~emacs_*~ tools.

** mcpkit-register-tool
:PROPERTIES:
:CUSTOM_ID: mcpkit-register-tool
:END:

#+BEGIN_SRC emacs-lisp
(mcpkit-register-tool NAME SERVICE-OR-NAME &rest REST &key DESCRIPTION INPUT-SCHEMA DECODE ENCODE ASYNC &allow-other-keys)
#+END_SRC

Register a tool ~NAME~ on ~SERVICE-OR-NAME~ with implementation ~BODY~.
- ~DESCRIPTION~: Human-readable documentation string.
- ~INPUT-SCHEMA~: JSON schema plist literal.
- ~DECODE~: Function to decode raw arguments plist before invoking handler.
- ~ENCODE~: Function to encode handler return value into an MCP content list.
- ~ASYNC~: If non-nil, ~BODY~ handles calling ~done~ callback asynchronously.

** mcpkit-start-service
:PROPERTIES:
:CUSTOM_ID: mcpkit-start-service
:END:

#+BEGIN_SRC emacs-lisp
(mcpkit-start-service NAME-OR-SERVICE &key (ON-COLLISION 'namespace) PORT)
#+END_SRC

Start or merge ~SERVICE~ into the active services set. ~ON-COLLISION~ specifies how tool name collisions are resolved:
- ~'namespace~: Prefixes tool names with ~<service-name>__~.
- ~'error~: Signals a ~user-error~ if an un-namespaced tool name collides with an existing active tool.

* Native Tool Search and Adaptive Gating
:PROPERTIES:
:CUSTOM_ID: tool-search-and-gating
:END:

When an MCP service hosts dozens of tools, listing the entire tool catalog in every ~tools/list~ payload rapidly degrades language model attention and consumes large amounts of context tokens.

=mcpkit-search= provides native, adaptive tool search and collation:
- *Adaptive Gating*: Controlled by ~mcpkit-search-mode~ (~auto~, ~always~, or ~never~, default ~auto~) and ~mcpkit-search-threshold~ (default ~25~). When the catalog exceeds the threshold, ~tools/list~ returns only pinned tools (~mcpkit-search-pinned-tools~) alongside a synthetic ~search_tools~ tool.
- *Orderless-Powered Filtering*: Searches match across tool names, owning services, descriptions, and parameter schema names using ~orderless-filter~ (or a built-in token fallback when ~orderless~ is unavailable). Multi-word out-of-order queries (e.g. ~"buffer append"~) match seamlessly.
- *Proxy and Sprite Collation*: Multi-process tools available across sub-daemon sprites are collated into a single canonical tool entry with process availability annotations (~[Available in processes: local, sprite:worker-1]~) rather than polluting the catalog with redundant duplicates.
- *Direct Execution*: Any registered tool remains directly callable via ~tools/call~ without requiring prior discovery.
- *Name Resolution*: ~invoke_tool~ and ~tools/call~ accept the exact namespaced name (~emacs__emacs_get_buffer~), the unprefixed name (~emacs_get_buffer~) when it maps to exactly one tool, or an alias from ~mcpkit-tool-aliases~ (old name to current name). Ambiguous bare names are rejected with the list of candidates. Aliases are resolver-only: they are never registered, so they do not appear in search or ~tools/list~. Packages add aliases with ~(mcpkit-register-tool-alias OLD NEW)~; ~(mcpkit-resolve-tool-name NAME &optional ACTIVE-SERVICES)~ returns the canonical name or nil.
- *Pinning*: ~mcpkit-search-pinned-tools~ entries may be namespaced, unprefixed, or aliased names; ~mcpkit-search-pinned-services~ (default nil) pins every tool of the listed services.
- *Usage Pinning*: With ~mcpkit-search-pinned-by-usage~ (default t) the most used tools are pinned too: up to ~mcpkit-search-pinned-usage-limit~ (8) tools with at least ~mcpkit-search-pinned-usage-min-calls~ (5) raw calls, ranked by decayed score (ties by name), skipping ~mcpkit-search-pinned-usage-exclude~ (the gateway tools, ~eval~ / ~emacs__eval~) and ~mcpkit-stats-hidden-tools~. With no recorded usage nothing extra is pinned. The effective pinned set is static pins, plus pinned services, plus usage pins. The usage set is a *snapshot* taken at the first ~tools/list~ after the services start and is not recomputed per request, because a changing tool list invalidates client prompt caches. It is dropped when a service starts or stops; ~M-x mcpkit-search-refresh-usage-pins~ recomputes it (and the catalog) on demand, otherwise it refreshes on daemon or service restart.
- *Namespace Discovery*: The always-pinned ~search_tools~ description carries a compact catalog from the active services (computed from the same snapshot): one line per service, ~- <service> (<N> tools): <description>; popular: <top 3 tools by score>~. ~popular~ is omitted without usage data; the catalog is capped at about 1500 characters (popular lists are dropped first, then descriptions truncated). ~search_tools~ with ~service~ and an empty ~query~ lists every tool in that service (when ~limit~ is not given). Disable with ~mcpkit-search-catalog-in-description~ (default t).
- *Compact Output*: ~search_tools~ renders parameters in the text as ~name (type, required)~ and omits the structured ~:tools~ copy unless ~mcpkit-search-structured-tools~ is non-nil. With no match it appends ~mcpkit-search-no-match-hint~ (by default pointing at ~emacs__eval~ as a last resort).

* Usage Statistics and Telemetry
:PROPERTIES:
:CUSTOM_ID: usage-statistics-and-telemetry
:END:

=mcpkit-stats= automatically tracks execution metrics for all tool invocations:
- *Metrics Tracked*: Call count, successes, errors, error percentage, latency percentiles (min, max, average, last), timestamp of last run, and a circular ring buffer of the last 10 errors with arguments.
- *Unknown Tools*: Calls to names that are not active tools (typos) are not recorded; the synthetic gateway tools are.
- *Argument Digests*: ~mcpkit-stats-argument-digesters~ maps a tool name to a function that turns the request arguments into a short key; counts per key are kept per tool and the top 10 appear in the detail view. The default digester for the eval tool records the first function called in the expression (e.g. ~sprite-create~), which shows which patterns deserve a dedicated tool.
- *Persistence*: Set ~mcpkit-stats-file~ (default nil, no persistence) to keep aggregates across restarts. Only aggregates are saved per tool (name, service, call/success/error counts, total/min/max duration, last call time, top 20 argument digests, decayed score); the recent-errors ring and request arguments are never written. The file holds one readable form ~(mcpkit-stats :version 1 :saved "TS" :tools (PLIST ...))~, written atomically with mode 0600. It is loaded (merged: counts added, earlier min, later max, digests unioned) when =mcpkit-stats= loads, saved after ~mcpkit-stats-save-interval~ (300) idle seconds when dirty, on ~kill-emacs-hook~, and by ~M-x mcpkit-stats-save~ / ~mcpkit-stats-load~ (the latter skips a file already merged unless given a prefix argument). Unknown versions or unreadable files are ignored with a logged warning. Sprite worker daemons never save or load, and only the live statistics table is ever persisted. With several daemons sharing one file the last writer wins. Example for ~bootstrap.el~, set before mcpkit loads:
  #+begin_src emacs-lisp
  (add-to-list 'sprite-state-mappings '(mcpkit-stats-file . "mcpkit-stats.eld"))
  #+end_src
  Any approach that sets ~mcpkit-stats-file~ before the library loads works; a value already set is respected.
- *Usage Score*: Each call adds 1 to a score that decays by ~0.5 ^ (elapsed / half-life)~ (~mcpkit-stats-half-life-days~, default 14); ~(mcpkit-stats-score TOOL &optional NOW)~ returns the current value. It drives usage pinning and the catalog's popular lists.
- *Reset*: ~mcpkit-stats-reset~ (all, or one tool; returns the cleared names) also rewrites the persisted file immediately; the dashboard ~c~ key uses it. There is deliberately no MCP reset tool: resetting is a rare, human-initiated operation.
- *Programmatic Access*: The ~mcpkit_stats~ MCP tool (and ~mcpkit-stats-rows~) return the table as structured rows (each with ~score~ and ~pinned~: ~static~, ~service~, ~usage~ or null), honoring ~mcpkit-stats-hidden-tools~. ~mcpkit_stats~ also returns ~persisted~ (file path or null), ~last_saved~ and ~usage_pins~.
- *Interactive Dashboard*: ~M-x mcpkit-stats~ opens ~*mcpkit-stats*~ in ~tabulated-list-mode~.
  - ~RET~ or ~v~: Inspect detailed tool metrics, schema, and error traces.
  - ~i~: Jump directly to the Elisp tool definition in source code.
  - ~l~: View and filter execution logs in ~*mcpkit-logs*~.
  - ~c~: Reset metrics (with confirmation).
  - ~g~: Refresh the view.
- *Detail View*: Buffer ~*mcpkit-stats-tool: <name>*~ displays interactive action buttons, timing stats, JSON input schema, and error trace history.

* Centralized Logging
:PROPERTIES:
:CUSTOM_ID: centralized-logging
:END:

All HTTP server processes and JSON-RPC dispatch events log directly to a unified buffer defined by ~mcpkit-log-buffer-name~ (default ~"*mcpkit-logs*~).
- Set ~mcpkit-log-split-services~ to ~t~ if you wish to mirror logs into individual per-service hidden buffers (~" *mcpkit-<service>*"~) in addition to ~*mcpkit-logs*~.
- Per-service buffers are hidden by default with a leading space to keep buffer lists uncluttered.
