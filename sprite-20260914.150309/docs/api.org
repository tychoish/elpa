**** [[file:../sprite.el::881][sprite-mode]] :command:
:PROPERTIES:
:CUSTOM_ID: sprite-mode
:END:

: (fn &optional ARG)

Global minor mode for managing sprite (subordinate Emacs daemon) state.

Enabling wires the registry into ‘savehist’ persistence and scans the filesystem for already-running sprites to populate the registry; disabling removes the ‘savehist’ hooks and variable registration. See ~sprite-mode-map~ and ~sprite-mode-command-map~.

This is a global minor mode.  If called interactively, toggle the ‘Sprite mode’ mode.  If the prefix argument is positive, enable the mode, and if it is zero or negative, disable the mode.

If called from Lisp, toggle the mode if /ARG/ is ‘toggle’.  Enable the mode if /ARG/ is nil, omitted, or is a positive number.  Disable the mode if /ARG/ is a negative number.

To check whether the minor mode is enabled in the current buffer, evaluate ‘(default-value 'sprite-mode)’.

The mode’s hook is called both when the mode is enabled and when it is disabled.

**** [[file:../sprite-direct.el::449][sprite-direct-promise-then]]
:PROPERTIES:
:CUSTOM_ID: sprite-direct-promise-then
:END:

: (fn PROMISE CALLBACK)

Arrange for /CALLBACK/ to run once /PROMISE/ leaves its ~:pending~ state. Unlike ~sprite-direct-promise-wait~, this does not block: it polls /PROMISE/ on a repeating timer (~sprite-direct-async-check-interval~) and cancels itself the first time ~sprite-direct-promise-pending-p~ is nil, at which point it calls /CALLBACK/ with two arguments, STATE (~:resolved~ or ~:rejected~) and VALUE (~sprite-direct-promise-value~, nil when rejected). The promise’s own sentinel still does the actual work of receiving the result; this only supplies the missing "notify me when done" callback on top of the pending/resolved/rejected state it already exposes.  Returns the timer, so the caller can ~cancel-timer~ it to abandon the callback.

** sprite-fleet

*** [[file:../sprite-fleet.el::46][sprite-fleet-mapcar-sprites]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-mapcar-sprites
:END:

: (fn FORM SPRITES &key TIMEOUT)

Evaluate /FORM/ in each of /SPRITES/ concurrently; return results in order. Mirrors ~mapcar~: one result per input, order preserved.  A sprite that times out or rejects contributes nil at its position.  /SPRITES/ is a list of ‘sprite’ structs, e.g. from ~sprite-resolve-list~.

*** [[file:../sprite-fleet.el::55][sprite-fleet-mapc]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-mapc
:END:

Evaluate FORM in each of SPRITES concurrently; discard results. Mirrors ~mapc~: dispatches to every sprite and returns SPRITES immediately without waiting for any of them to settle.  SPRITES is a list of ‘sprite’ structs, e.g. from ~sprite-resolve-list~.

*** [[file:../sprite-fleet.el::64][sprite-fleet-mapcar]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-mapcar
:END:

: (fn FN-OR-FORM ITEMS &key FLEET-SIZE SPRITES TIMEOUT ASYNC)

Evaluate /FN-OR-FORM/ for each item in /ITEMS/ using a fleet of sprites. /FN-OR-FORM/ can be a unary function/lambda symbol or a form to evaluate. When /FN-OR-FORM/ is a function symbol or lambda, each item is passed as an arg. When /FN-OR-FORM/ is a form containing ‘item’ or ‘_’, that form is evaluated remotely with the item bound.

/FLEET-SIZE/ is the maximum number of concurrent sprites to use (defaults to ~sprite-max-count~ or the length of /ITEMS/).

/SPRITES/ is an optional list of sprite structs or target name strings to use as the worker fleet.  When omitted, sprites are obtained via ~sprite-get-or-create-fleet~.

/TIMEOUT/ is passed to ~sprite-future-wait~ when operating synchronously.

If /ASYNC/ is non-nil, returns a ‘sprite-future’ immediately that resolves to the ordered list of results when all items complete.  Otherwise, blocks and returns the ordered list of results.

*** [[file:../sprite-fleet.el::123][sprite-fleet-let]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-let
:END:

: (fn BINDINGS &rest BODY)

Like ~let~, but each binding’s value comes from a concurrent sprite eval. Each element of /BINDINGS/ is (VAR SPRITE FORM): SPRITE is an expression evaluated to a sprite full-name string, FORM is unquoted and evaluated remotely (quoted automatically, as with ~with-sprite~).  All FORMs are dispatched in parallel; /BODY/ runs once every binding has settled, with VAR bound to its resolved value.

*** [[file:../sprite-future.el::105][sprite-future-then]]
:PROPERTIES:
:CUSTOM_ID: sprite-future-then
:END:

: (fn FUTURE ON-RESOLVE &optional ON-REJECT)

Chain /ON-RESOLVE/ (and optionally /ON-REJECT/) onto /FUTURE/. Returns a new ‘sprite-future’ that settles once /FUTURE/ does: /ON-RESOLVE/ runs (and its return value resolves the new future) if /FUTURE/ resolves; /ON-REJECT/ runs if /FUTURE/ rejects.  Whichever callback is omitted passes /FUTURE/’s own state/value through unchanged.  If /FUTURE/ has already settled, the callback runs immediately and the new future settles synchronously; otherwise it runs later, when /FUTURE/ settles.

:CUSTOM_ID: sprite-future-await

: (fn FUTURE)

Inside a ~sprite-future-async-defun~ body, suspend until /FUTURE/ settles. Resumes with /FUTURE/’s resolved value when it resolves.  When /FUTURE/ rejects, signals ‘sprite-future-rejected’ with the rejection value at this point, so a ~condition-case~ wrapping ~sprite-future-await~ can catch it.
