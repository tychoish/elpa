** sprite-batch

*** [[file:../sprite-batch.el::51][sprite-run-batch]]
:PROPERTIES:
:CUSTOM_ID: sprite-run-batch
:END:

: (fn &key OPERATIONS OPS (DELAY 0.1) RUN-AFTER INITIAL-DELAY ARGS ARGLIST ON-DONE FRAME BUFFER (LOG-PREFIX "[run]"))

Run /OPERATIONS/ (or /OPS/) in order, yielding between each in interactive sessions. /OPERATIONS/ may be a list of functions, a single function, or a symbol whose value is a list of functions (such as a hook). Supported keyword arguments: :operations or :ops, :run-after or :initial-delay SECONDS (defaults to :delay), :delay SECONDS (defaults to 0.1), :args or :arglist LIST or ATOM (arguments passed to non-nilary operations), :on-done FUNCTION, :frame FRAME, :buffer BUFFER (`temp' executes in `with-temp-buffer', a buffer object or string name executes in `with-current-buffer'), :log-prefix STRING (defaults to "[run]"). In noninteractive (batch) sessions, runs all operations synchronously. Return a cancellation function.

**** [[file:../sprite-direct.el::449][sprite-direct-promise-then]]
:PROPERTIES:
:CUSTOM_ID: sprite-direct-promise-then
:END:

: (fn PROMISE CALLBACK)

Arrange for /CALLBACK/ to run once /PROMISE/ leaves its ~:pending~ state. Unlike ~sprite-direct-promise-wait~, this does not block: it polls /PROMISE/ on a repeating timer (~sprite-direct-async-check-interval~) and cancels itself the first time ~sprite-direct-promise-pending-p~ is nil, at which point it calls /CALLBACK/ with two arguments, STATE (~:resolved~ or ~:rejected~) and VALUE (~sprite-direct-promise-value~, nil when rejected). The promise’s own sentinel still does the actual work of receiving the result; this only supplies the missing "notify me when done" callback on top of the pending/resolved/rejected state it already exposes.  Returns the timer, so the caller can ~cancel-timer~ it to abandon the callback.

**** [[file:../sprite-fleet.el::376][sprite-fleet-pool]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-pool
:END:

: (fn FN-OR-FORM ITEMS &key FLEET-SIZE SPRITES (DELAY 0.0) (ORDER 'preserve) (ERROR-POLICY :collect-nil) ON-ITEM ON-DONE)

Create and start a ‘sprite-fleet-handle’ executing /FN-OR-FORM/ over /ITEMS/. /FLEET-SIZE/ is the maximum number of concurrent sprites. /SPRITES/ is a list of sprite structs or target name strings. DELAY is the yielding delay in seconds between dispatches (default 0.0). ORDER specifies result ordering: ‘preserve’ (default), ‘fifo’, ‘lifo’, or ‘unordered’. ERROR-POLICY specifies failure behavior: ~:collect-nil~ (default), ~:collect-error~, or ~:abort~. /ON-ITEM/ is an optional callback (lambda (item result idx)). /ON-DONE/ is an optional callback (lambda (results)).

Returns a ‘sprite-fleet-handle’.

**** [[file:../sprite-fleet.el::444][sprite-fleet-map]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-map
:END:

: (fn FN-OR-FORM ITEMS &key FLEET-SIZE SPRITES (DELAY 0.0) (ORDER 'preserve) (ERROR-POLICY :collect-nil) ON-ITEM ON-DONE WAIT TIMEOUT (ASYNC t))

Evaluate /FN-OR-FORM/ over /ITEMS/ across a fleet of sprites. By default returns a ‘sprite-future’ that resolves to the ordered results. The future’s controller is accessible via ~sprite-future-fleet-handle~.

If /WAIT/ is non-nil (or ASYNC is nil), blocks until complete and returns the results.

**** [[file:../sprite-fleet.el::469][sprite-fleet-each]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-each
:END:

: (fn FN-OR-FORM ITEMS &key FLEET-SIZE SPRITES (DELAY 0.0) (ERROR-POLICY :collect-nil) ON-ITEM ON-DONE)

Stream evaluation of /FN-OR-FORM/ over /ITEMS/ across a fleet of sprites. Returns the controller ‘sprite-fleet-handle’ immediately for flow control (~sprite-fleet-pause~, ~sprite-fleet-resume~, ~sprite-fleet-cancel~). Results are streamed to /ON-ITEM/ as each worker completes.

**** [[file:../sprite-fleet.el::488][sprite-fleet-mapcar]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-mapcar
:END:

: (fn FN-OR-FORM ITEMS &key FLEET-SIZE SPRITES TIMEOUT ASYNC (DELAY 0.0) (ORDER 'preserve) (ERROR-POLICY :collect-nil) ON-ITEM ON-DONE)

Evaluate /FN-OR-FORM/ for each item in /ITEMS/ using a fleet of sprites. Mirrors ~mapcar~ across the daemon fleet.

Preserves backward compatibility: defaults to synchronous execution blocking until all results settle unless /ASYNC/ is non-nil. Delegates to ~sprite-fleet-pool~ and the yielding stepper engine.

**** [[file:../sprite-fleet.el::514][sprite-fleet-mapcar-sprites]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-mapcar-sprites
:END:

: (fn FORM SPRITES &key TIMEOUT)

Evaluate /FORM/ in each of /SPRITES/ concurrently; return results in order. Mirrors ~mapcar~: one result per input, order preserved.  A sprite that times out or rejects contributes nil at its position.  /SPRITES/ is a list of ‘sprite’ structs, e.g. from ~sprite-resolve-list~.

**** [[file:../sprite-fleet.el::523][sprite-fleet-mapc]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-mapc
:END:

Evaluate FORM in each of SPRITES concurrently; discard results. Mirrors ~mapc~: dispatches to every sprite and returns SPRITES immediately without waiting for any of them to settle.  SPRITES is a list of ‘sprite’ structs, e.g. from ~sprite-resolve-list~.

**** [[file:../sprite-fleet.el::531][sprite-fleet-let]]
:PROPERTIES:
:CUSTOM_ID: sprite-fleet-let
:END:

: (fn BINDINGS &rest BODY)

Like ~let~, but each binding’s value comes from a concurrent sprite eval. Each element of /BINDINGS/ is (VAR SPRITE FORM): SPRITE is an expression evaluated to a sprite full-name string, FORM is unquoted and evaluated remotely (quoted automatically, as with ~with-sprite~).  All FORMs are dispatched in parallel; /BODY/ runs once every binding has settled, with VAR bound to its resolved value.

:PROPERTIES:
:CUSTOM_ID: sprite-future-then
:END:

: (fn FUTURE ON-RESOLVE &optional ON-REJECT)

Chain /ON-RESOLVE/ (and optionally /ON-REJECT/) onto /FUTURE/. Returns a new ‘sprite-future’ that settles once /FUTURE/ does: /ON-RESOLVE/ runs (and its return value resolves the new future) if /FUTURE/ resolves; /ON-REJECT/ runs if /FUTURE/ rejects. If /FUTURE/ has already settled, the callback runs immediately and the new future settles synchronously; otherwise it runs later, when /FUTURE/ settles.
