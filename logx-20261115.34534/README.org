High-performance, zero-allocation structured logging and line-oriented JSON viewer for GNU Emacs.

* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

=logx= provides a high-performance structured logging pipeline, pluggable multi-output
backends, and an interactive log viewer ecosystem for GNU Emacs. It is built strictly on
GNU Emacs 29+ standard library primitives (=json.c=, =ring.el=, =map.el=, =cl-lib=) with
zero external package dependencies.

** Features
- *Zero-Allocation Disabled Paths*: Bitmask severity gating evaluates in ~0.4 µs with zero allocations when below active threshold.
- *Primary Ingress In-Memory Ring Buffer*: Uses core =ring.el= for O(1) in-memory retention (~3.9 µs latency) without custom vector pointer bookkeeping.
- *Pluggable Output Backends*:
  - *Ring Buffer* (=ring=): Primary in-memory circular storage; always active.
  - *JSON Lines File* (=file=): Atomic batch-flushed log file writer.
  - *systemd-journald* (=journald=): Direct Unix domain datagram socket writer (=/run/systemd/journal/socket=) with structured metadata.
  - *Legacy syslog* (=syslog=): Standard RFC 3164 datagram socket writer (=/dev/log=).
  - *Custom Backends*: Register arbitrary batch dispatchers via =logx-register-backend=.
- *Asynchronous Batch Flushing & Backpressure*: Decouples disk/socket I/O from the UI thread using background timer or thread transports (~55x faster than synchronous writes under pressure), guarded with configurable backpressure policies (=:drop-oldest= or =:yield=).
- *Strict Architectural Decoupling*:
  - =logx.el=: Core structured logger, severity macros, ring buffer, backend registry, and async engine. Completely headless.
  - =jsonl-view.el=: Generic, high-performance line-oriented JSON viewer with inline expandable disclosure widgets and full-record detail buffer (=*jsonl-info*=). Contains zero log concepts.
  - =logx-view.el=: Specialized log viewer layered on =jsonl-view-mode=. Provides semantic faces (inheriting cleanly from standard faces without hardcoded hex colors), interactive level/category filtering, timestamp display cycling, and live throttled streaming.
  - =logx-alert.el=: Optional integration sink routing =alert.el= notifications into =logx=.
- *Extended Severity Scale*: Full 8-level hierarchy (=debug=, =info=, =notice=, =warn=, =error=, =critical=, =alert=, =fatal=).
- *Cycle-Safe Object Sanitizer*: Defends against self-referential or cyclic Elisp data structures during serialization.

* Configuration
:PROPERTIES:
:CUSTOM_ID: configuration
:END:

#+BEGIN_SRC emacs-lisp
(use-package logx
  :defer t
  :commands (logx-show-logs logx-fork-filtered-buffer)
  :init
  ;; Default minimum severity threshold
  (setq logx-default-level 'info)
  ;; Retain 10,000 events in memory
  (setq logx-ring-buffer-size 10000)
  ;; Optional: persistent disk log sink
  (setq logx-log-file (expand-file-name "logs/emacs.jsonl" user-emacs-directory))
  ;; Enable asynchronous batch flushing (recommended)
  (setq logx-async-mode t
        logx-async-transport 'timer
        logx-async-flush-interval 0.05))

(use-package jsonl-view
  :defer t
  :mode ("\\.jsonl\\'" . jsonl-view-mode))

(use-package logx-view
  :defer t
  :after logx
  :bind (:map logx-view-mode-map
              ("RET" . logx-view-jump-to-source)
              ("t"   . logx-view-cycle-timestamp-mode)
              ("l"   . logx-view-filter-level)
              ("c"   . logx-view-filter-category)
              ("C"   . logx-view-clear-filters)
              ("B"   . logx-fork-filtered-buffer)))
#+END_SRC

** Structured Logging
:PROPERTIES:
:CUSTOM_ID: structured-logging
:END:

Emit structured events with key-value pairs. Keys can be keyword symbols, strings, or numbers:

#+BEGIN_SRC emacs-lisp
(require 'logx)

;; Basic info logging
(logx-info :cat 'auth :msg "User logged in" :uid 1001 :ip "127.0.0.1")

;; Warning with telemetry attributes
(logx-warn :cat 'db :msg "Slow query detected" :duration-ms 4200 :query "SELECT ...")

;; High severity levels
(logx-critical :cat 'billing :msg "Gateway unresponsive" :retries 3)
(logx-alert :cat 'security :msg "Multiple failed authentications" :target "admin")
(logx-fatal :cat 'system :msg "Out of memory" :free-bytes 0)
#+END_SRC

** Pluggable Output Backends
:PROPERTIES:
:CUSTOM_ID: pluggable-output-backends
:END:

By default, events are written immediately to the primary in-memory ring buffer. Additional
destinations can be enabled or registered dynamically:

#+BEGIN_SRC emacs-lisp
;; Enable direct socket delivery to systemd-journald
(logx-enable-backend 'journald)

;; Enable direct RFC 3164 socket delivery to syslog
(logx-enable-backend 'syslog)

;; Register a custom telemetry backend
(logx-register-backend 'cloud-telemetry
  (lambda (events)
    (message "Forwarding %d events to remote collector" (length events))))

;; Synchronously flush all pending asynchronous writes immediately
(logx-flush)
#+END_SRC

** Viewing Logs Interactively
:PROPERTIES:
:CUSTOM_ID: viewing-logs-interactively
:END:

Open the primary live viewer buffer:

#+BEGIN_SRC emacs-lisp
(logx-show-logs)
#+END_SRC

In =logx-view-mode=:
- =RET=: Jump directly to the call-site source code location in another window.
- =t=: Cycle timestamp presentation format (=Time-of-day= -> =Delta (+45ms)= -> =ISO-8601=).
- =l=: Filter buffer by minimum severity level.
- =c=: Filter buffer by category regex.
- =C=: Clear all active filters.
- =i=: Open side-window detail inspector (=*jsonl-info*=) pretty-printing full record.
- =w=: Copy current line's JSON string to the kill-ring.
- =B=: Fork the view into a dedicated live filtered buffer (e.g. =*logs:auth*=).

** Generic Line-Oriented JSON Viewing
:PROPERTIES:
:CUSTOM_ID: generic-line-oriented-json-viewing
:END:

=jsonl-view= can be used independently of =logx= to browse any JSON Lines file or buffer:

#+BEGIN_SRC emacs-lisp
(find-file "production-export.jsonl")
;; Automatically activates jsonl-view-mode

Use =TAB= to expand/collapse complex nested JSON values inline, or =i= to inspect them formatted in a dedicated buffer.

* Performance & Benchmarks
:PROPERTIES:
:CUSTOM_ID: performance-and-benchmarks
:END:

Comprehensive comparative benchmarks against =log4e=, =elog=, =emacs-lgr=, and built-in
primitives are detailed in [[file:docs/benchmarks.org][docs/benchmarks.org]].

Key benchmark highlights on GNU Emacs 31.1:
- *Disabled Macro Gating*: ~2,463,000 ops/sec (~0.4 µs/op) with zero allocations.
- *Active In-Memory Ring Logging*: ~253,500 ops/sec (~3.9 µs/op) — within 1 µs of C =message=.
- *Async Batch Flushing vs Sync Disk Writes*: Async flushing achieves ~253,500 ops/sec under pressure (*53x faster* than synchronous disk writes at ~4,760 ops/sec).
- *Comparison to Existing Libraries*: =logx= is *10x to 20x faster* than =emacs-lgr=, =elog=, and =log4e=.
