* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

=gptel-mcp= bridges [[https://github.com/tychoish/mcpkit][mcpkit.el]] service and tool registrations onto [[https://github.com/karthink/gptel][gptel]]'s LLM
tool-calling framework.

Instead of manually duplicating argument schemas and handlers across both frameworks,
=gptel-mcp= automatically converts ~mcpkit-tool~ definitions into ~gptel-tool~ structs
via ~gptel-make-tool~. Tools defined for MCP servers can thus be used immediately
by LLMs inside gptel chat sessions.

Key features include:

- *Automatic Schema Conversion*: Recursively converts JSON-schema object definitions
  (~:input-schema~) from mcpkit into gptel's ~:args~ format, mapping schema types
  to Lisp symbols and preserving parameter metadata and optionality.
- *Asynchronous Invocation Wrapper*: Adapts mcpkit's callback-based handler pattern
  (~handler-args callback~) into gptel's positional asynchronous calling convention
  (~callback &rest args~).
- *Batch Service Registration*: Registers all tools attached to an ~mcpkit-service~
  in a single call via ~gptel-mcp-register-service-tools~, grouping them under a
  gptel category matching the service name.

** ELPAish (Recommended)
:PROPERTIES:
:CUSTOM_ID: elpaish-recommended
:END:

Add the ELPAish repository to ~package-archives~:

#+BEGIN_SRC emacs-lisp
(add-to-list 'package-archives
             '("elpaish" . "https://tychoish.github.io/elpaish/snapshot/") t)
(package-refresh-contents)
#+END_SRC

Install with =package-install=:

#+BEGIN_SRC emacs-lisp
(package-install 'gptel-mcp)
#+END_SRC

To verify package signatures, import the ELPAish signing key into
=package.el='s keyring and enable signature checking:

#+BEGIN_SRC emacs-lisp
(url-copy-file "https://tychoish.github.io/elpaish/elpaish-keyring.gpg"
               "elpaish-keyring.gpg" t)
(package-import-keyring "elpaish-keyring.gpg")
(setq package-check-signature t)
#+END_SRC

** use-package with VC
:PROPERTIES:
:CUSTOM_ID: use-package-with-vc
:END:

Requires Emacs 30+. Installs on first load if not already present:

#+BEGIN_SRC emacs-lisp
(use-package gptel-mcp
  :vc (:url "https://github.com/tychoish/gptel-mcp")
  :after (gptel mcpkit))
#+END_SRC

** Manual Installation
:PROPERTIES:
:CUSTOM_ID: manual-installation
:END:

Clone the repository into your =site-lisp= directory:

#+BEGIN_SRC sh
git clone https://github.com/tychoish/gptel-mcp ~/.emacs.d/site-lisp/gptel-mcp
#+END_SRC

Add it to your ~load-path~:

#+BEGIN_SRC emacs-lisp
(add-to-list 'load-path "~/.emacs.d/site-lisp/gptel-mcp")
(require 'gptel-mcp)
#+END_SRC

With Emacs 29.1+, you can also use ~package-vc-install~:

#+BEGIN_SRC emacs-lisp
(package-vc-install '(gptel-mcp
                      :url "https://github.com/tychoish/gptel-mcp"))
#+END_SRC

* Configuration
:PROPERTIES:
:CUSTOM_ID: configuration
:END:

Configure =gptel-mcp= using ~use-package~:

#+BEGIN_SRC emacs-lisp
(use-package gptel-mcp
  :ensure t
  :after (gptel mcpkit)
  :commands (gptel-mcp-register-service-tools)
  :config
  ;; Bridge tools from mcpkit services into gptel
  (with-eval-after-load 'mcpkit-emacs
    (gptel-mcp-register-service-tools 'emacs)))
#+END_SRC

** Key Options & Customization
:PROPERTIES:
:CUSTOM_ID: key-options--customization
:END:

- *Tool Categories*: Tools registered via ~gptel-mcp-register-service-tools~
  are assigned a gptel category matching the ~mcpkit-service~ name (e.g. ~"emacs"~
  or ~"denote"~). You can selectively enable or disable categories in the gptel
  transient menu (=C-u M-x gptel-send=).
- *Asynchronous Execution*: All bridged tools execute asynchronously, preserving
  Emacs responsiveness during long-running tool execution or network calls.

** Defining an mcpkit Tool
:PROPERTIES:
:CUSTOM_ID: defining-an-mcpkit-tool
:END:

Define a service and tool using =mcpkit=:

#+BEGIN_SRC emacs-lisp
(require 'mcpkit)

(mcpkit-define-service 'calc-service :description "Calculator tools")

(mcpkit-register-tool 'calculate_sum 'calc-service
  :description "Add two integers together."
  :input-schema '(:type "object"
                  :properties (:a (:type "integer" :description "First addend")
                               :b (:type "integer" :description "Second addend"))
                  :required ["a" "b"])
  (+ (plist-get args :a) (plist-get args :b)))
#+END_SRC

** Bridging Tools to gptel
:PROPERTIES:
:CUSTOM_ID: bridging-tools-to-gptel
:END:

Bridge all tools registered on ~calc-service~ to gptel:

#+BEGIN_SRC emacs-lisp
(require 'gptel-mcp)

;; Generates a gptel-tool and registers it with gptel
(gptel-mcp-register-service-tools 'calc-service)
#+END_SRC

** Using Tools with LLM Queries
:PROPERTIES:
:CUSTOM_ID: using-tools-with-llm-queries
:END:

Once registered, the tool is available in gptel's tool-calling system.
In an active gptel chat session with tool calling enabled:

#+BEGIN_EXAMPLE
User: What is 42 + 58?
LLM: [Calls calculate_sum(a=42, b=58)]
Response: The sum of 42 and 58 is 100.
#+END_EXAMPLE

#+RESULTS:
** [[file:gptel-mcp.el::100][gptel-mcp-register-service-tools]]
:PROPERTIES:
:CUSTOM_ID: gptel-mcp-register-service-tools
:END:

Register a gptel tool for every ‘mcpkit-tool’ on SERVICE-NAME. SERVICE-NAME is resolved via ~mcpkit-get-service~ (a symbol, string, or ‘mcpkit-service’ instance).  Each generated gptel tool wraps the underlying mcpkit tool’s handler, translating its JSON-schema ‘input-schema’ into gptel’s :args format and its callback-based ~handler~ into gptel’s asynchronous :function calling convention.  Tools are grouped in gptel’s UI under a :category matching the service name.

Return the list of ‘gptel-tool’ structs created.
