* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

=builder= is an extensible compilation runner, task discovery framework, and
process isolation environment for GNU Emacs. It replaces static compilation
invocations with context-aware candidate generators, provides history and
priority-ranked candidate completion, enhances Emacs compilation mode with
modern error regexps and ANSI formatting, and integrates with the Model Context
Protocol (MCP) via [[https://github.com/tychoish/mcpkit][mcpkit]].

* Key Features
:PROPERTIES:
:CUSTOM_ID: features
:END:

- *Context-Aware Candidate Discovery*: Dynamically inspects project layout,
  detecting Makefiles, Justfiles, Go modules/packages, Rust Cargo crates,
  Python pyproject/pip environments, Org Babel source blocks, Markdown/Vale
  linting, and Emacs Lisp test suites.
- *Ergonomic Candidate Selection*: Uses [[https://github.com/tychoish/annotated-completing-read][annotated-completing-read]] to present
  richly annotated commands sorted by recency, task priority, and command length.
- *Compilation Enhancements (`builder-mode`)*: Global minor mode providing ANSI
  colorization, background process completion alerts, improved compilation
  read-command advice, and specialized error matchers (Go test failures, Go
  runtime panics, Rust pretty-log stack traces).
- *In-Session Package Reloading*: Reloads in-development Emacs Lisp packages
  directly into the running session without restarts, tracking loaded features,
  load-paths, and dependency closures.
- *Isolated Verification*: Executes byte-compile, load checks, and ERT test
  suites in clean subprocesses (~emacs --batch~) to verify package declarations
  without pollution from interactive state.
- *Model Context Protocol (MCP) Server*: Optional =builder-mcp= service exposing
  task discovery, non-blocking asynchronous compilation execution, buffer
  reading, and completion polling to LLM assistants.

* Architecture & Modules
:PROPERTIES:
:CUSTOM_ID: architecture
:END:

=builder= is organized into focused, modular libraries:

| File | Purpose |
|--------------------+-----------------------------------------------------------------|
| =builder-core.el= | Candidate struct, registry, caching, selection, compilation driver|
| =builder-mode.el= | Global minor mode, error regexps, ANSI colorization, keybindings |
| =builder-elisp.el= | Path resolver registry, package reload, test, compile, lint |
| =builder-isolate-elisp.el=| Subprocess & daemon isolation runners, fast package test runner, clean-elc, native compile |
| =builder-elisp-check.el= | Structured, cached package checks (parens, compile, checkdoc, package-lint, relint, static) |
| =builder-scaffold.el= | Package repository and CI workflow scaffolding |
| =builder-docs.el= | Org link validation and =docs/api.org= generation |
| =builder-tasks.el= | 24 declarative candidate generator pipelines for supported tools|
| =builder-mcp.el= | Model Context Protocol service on port 8765 via =mcpkit= |
| =builder-elpaish.el= | =elpaish_*= MCP tools; registered only when ELPAish is installed |
| =builder.el= | Primary package entry point, autoloads, and metadata |

#+begin_src emacs-lisp
(use-package builder
  :ensure t
  :commands (builder builder-compile-project)
  :config
  (builder-mode 1))

* Usage
:PROPERTIES:
:CUSTOM_ID: usage
:END:

** Interactive Compilation
- =M-x builder= or =M-x builder-compile-project=: Prompts for compilation
  command pre-populated with context-derived candidate actions, then prompts for
  compilation buffer name.
- In =compilation-mode= buffers:
  - =d=: Run =builder-change-directory= to repoint the compilation buffer.
  - =C=: Recompile with standard prompt.

** Coverage
When =builder-mode= is active, =builder-coverage-modes= controls which major
modes automatically enable =cov-mode=.  Its default is =(go-ts-mode)=; set it
to nil to disable automatic activation.  Customize =builder-coverage-display=,
=builder-coverage-lcov-file=, and =builder-coverage-search-paths= to change
the settings applied when =cov= loads.  Install =cov= separately to use this
integration.  Change these settings before enabling =builder-mode=, or disable
and re-enable it after changing them.

In Go tree-sitter buffers, =C-c C-t c= runs
=builder-go-coverage-and-convert=.  It writes =coverage/lcov.info= and refreshes
coverage overlays after a successful run.

** Extending Candidate Generators
Define new candidate generators with =builder-register-candidates=:

#+begin_src emacs-lisp
(builder-register-candidates
 :name "custom-linter"
 :predicate (file-exists-p (expand-file-name ".custom-lint" project-root-directory))
 :pipeline
 (list (make-builder-candidate
        :name "run custom linter"
        :command "custom-lint ./..."
        :directory project-root-directory
        :priority 1
        :annotation "run project-specific linter")))
#+end_src

** Elisp Path Resolution
Register custom package path resolvers for non-standard project layouts:

#+begin_src emacs-lisp
(builder-register-elisp-package-path-resolver
 (lambda (root &optional name)
   (let ((candidate (expand-file-name "src/lisp" root)))
     (when (file-directory-p candidate)
       candidate))))
#+end_src

** MCP Tools
When =mcpkit= is loaded, =builder-mcp= registers the ='builder= service exposing:

Task running:
- =discover_tasks=: Returns discovered candidate tasks as JSON plists.
- =run_task=: Spawns a non-interactive compilation process in a named buffer.
- =read_buffer=: Reads lines, exit status, line count, and tail output.
- =await_build=: Asynchronously waits for process termination with timeout.
- =list_buffers=: Lists all active compilation buffers.

Emacs Lisp packages:
- =elisp_preflight=: One in-process call running check-parens, byte-compile,
  checkdoc, package-lint, relint (when installed) and builder's static checks.
  Returns structured findings (tool, file, line, severity, message).  Findings
  are cached per file, so a re-run after an edit only re-checks what changed;
  pass =cache= false to force, or =isolated= true for a fresh subprocess.
- =builder_run_tests=: With a =root=, loads the package and runs its ERT tests
  in a fast isolated subprocess (no =package-initialize=) and returns counts
  plus each failing test and its condition.  =selector= (regexp), =prefix= and
  =glob= narrow the run.  Without a root it runs an ERT selector form in the
  live Emacs.
- =builder_package_build=: Builds an installable =.tar= into =build/packages/=
  (=action= =build=), cleans artifacts (=clean=), or both (=rebuild=).
- =builder_package_unused=: Lists installed packages outside the dependency
  closure of your selected packages.
- =builder_byte_compile=, =builder_check_parens=, =builder_load_file=:
  single-file checks (byte-compile and load run in an isolated subprocess).
- =elisp_package_spinout= and =elisp_ci_setup=: Scaffold a package repository
  and a GitHub Actions workflow.  Both default to =dry_run=; neither runs git
  or touches the network, and existing files are never overwritten (a workflow
  is replaced only with =overwrite=).  Author, GitHub owner, CI action
  repository and Emacs versions are customizable under =builder-scaffold=.
- =doc_validate=: Checks Org links (file targets, line numbers, =CUSTOM_ID=
  and heading anchors) in =README.org= and =docs/*.org=.
- =doc_generate_api=: Scaffolds or regenerates =docs/api.org= with
  =org-docsgen=.

ELPAish (registered only when =elpaish-ops= is installed; a separate =elpaish=
service, ELPAish itself stays optional and is loaded on first call):
- =elpaish_status=: per-recipe commit delta against the last build; local only,
  never clones or fetches.
- =elpaish_rebuild=: rebuild archives for one package, those behind HEAD, or all.
- =elpaish_upgrade=: upgrade named or all installed packages.
- =elpaish_workflow_dispatch=: dispatch the ELPAish repository's workflow.
- =elpaish_recipe=: format an =elpaish-register-package= form.

Worktrees named =<repo>/.wt/<topic>= are recognized as the package =<repo>=.
